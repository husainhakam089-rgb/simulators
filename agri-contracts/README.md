# عقود ووصولات الآلات الزراعية — معرض البركة

تطبيق عربي بالكامل (RTL) يعمل **بلا إنترنت**، يستبدل الدفتر الورقي بطباعة
مرتّبة على نفس شكل العقد، مع إدخال سريع يعتمد على الاختيار بدل الكتابة.

- **عقد بيع كامل** على ورقة A4 — للترتكترات والحاصدات.
- **وصل صغير** على نصف ورقة A4 — للأدوات والملحقات، مع خيار وصلين في الورقة
  الواحدة وخط قص بينهما.

بُني بتقنيات الويب (HTML + CSS + JavaScript) وغُلّف بـ **Capacitor** ليخرج
APK أندرويد. الكود نفسه يصلح لاحقاً لنسخة سطح مكتب عبر Tauri أو Electron.

---

## ملف واحد — الأسهل للتعديل

`عقود-البركة.html` نسخة مكتفية بذاتها: الأنماط والخطوط والبرمجة كلها في ملف
واحد. **افتحه بالمتصفح مباشرة ويعمل** — بلا خادم وبلا تنصيب وبلا إنترنت.
انقله بالواتساب أو على فلاشة كما هو.

أقسامه مفصولة بعناوين واضحة بين نجمات، ابحث عنها في المحرّر:

| القسم | ماذا فيه |
|---|---|
| `***** 1) الخطوط *****` | سطور base64 طويلة — اطوِها ولا تعدّلها |
| `***** 2) أنماط الواجهة *****` | ألوان التطبيق ومقاساته |
| `***** 3) أنماط الطباعة *****` | قالب A4 — **هنا يكون الضبط بعد أول طبعة** |
| `***** 4) برمجة التطبيق *****` | الشاشات والقوائم والحفظ والطباعة |

يُعاد توليده من المصدر المفصول في `www/` بـ:

```bash
npm run build:single
```

> التوليد باتجاه واحد: من `www/` إلى الملف الواحد. إن عدّلت الملف الواحد
> مباشرة، لا تشغّل `build:single` بعدها لأنه سيكتب فوق تعديلك — أو انقل
> التعديل إلى `www/` أيضاً.

لإخراج APK من الملف الواحد بعد تعديله:

```bash
npm run android:apk:single
```

## التشغيل على الحاسبة (للتجربة والتطوير)

```bash
cd agri-contracts
npm install
npm run serve       # ثم افتح http://localhost:5173
```

كل شيء يعمل في المتصفح: الإدخال، الحفظ، المعاينة، والطباعة عبر نافذة
طباعة المتصفح.

## بناء APK

يحتاج Android SDK وJava 21.

```bash
cd agri-contracts
npm install
npx cap add android              # أول مرة فقط
node scripts/apply-android-extras.mjs
npm run android:apk              # يخرج APK في android/app/build/outputs/apk/debug/
```

بعد أي تعديل على ملفات `www/`:

```bash
npm run cap:sync                 # ينسخ الملفات ويعيد دمج ملحق الطباعة
npm run android:apk
```

### بلا تنصيب أي شيء

كل دفعة إلى المستودع تبني APK جديداً تلقائياً وتنشره على رابط ثابت:

**<https://github.com/husainhakam089-rgb/simulators/releases/tag/apk-latest>**

افتح الرابط من الهاتف ونزّل `albaraka-contracts.apk` مباشرة، ثم اسمح
بالتثبيت من مصادر غير معروفة. الملف موقّع بمفتاح التجربة (debug) وهو كافٍ
للتثبيت اليدوي؛ لرفعه إلى متجر Play لاحقاً يلزم توقيعه بمفتاح إصدار.

يمكن أيضاً تشغيل الإجراء يدوياً من تبويب **Actions** في GitHub.

## رسومات العقد

رسومات الدفتر الأصلي **مستخرجة ومضمّنة في التطبيق**، تُطبع تلقائياً بلا أي
إعداد: الترتكتر يساراً، شعار «معرض البركة» وسطاً، السيارة يميناً، وزخرفة
الزاوية في الزوايا الأربع (صورة واحدة تُقلب أفقياً وعمودياً).

**الوصل الصغير بلا رسومات** — نصّي بحت، بطلب صاحب المعرض.

الرسومات في `www/assets/art/`، ومضمّنة كـ data URL في `www/js/artwork.js`
لأن مستند الطباعة يُحمَّل منفصلاً عن التطبيق فلا تصله المسارات النسبية.

### إعادة الاستخراج من صورة أوضح

الرسومات الحالية مستخرجة من صورة هاتف بدقة 899×1599، وهي مقبولة للطباعة
لكنها ليست حادة كالأصل. **صورة أوضح تعطي نتيجة أفضل مباشرة** — والأفضل منها
ملفات جاهزة من المطبعة التي طبعت الدفتر.

```bash
pip install Pillow numpy
# استبدل artwork-source/contract-scan.jpg بالصورة الجديدة
# واضبط إحداثيات CROPS في أعلى السكربت لتطابقها
python3 scripts/extract-artwork.py
npm run build:single
```

السكربت يعيد بناء `www/assets/art/` و`www/js/artwork.js` و`رسومات-العقد.zip`
دفعة واحدة. ما يفعله بكل رسم:

- يقيس لون الورقة من **شريط حواف الاقتصاص** وحده ويجعله أبيض نقياً، فلا يظهر
  مستطيل رمادي حول الرسم على الصفحة.
- زخرفة الزاوية تُعامَل بطريقة مختلفة: تُزال تدرّجات إضاءة التصوير، ثم يُفصل
  الحبر عن بياض الورقة لتصير **خلفيتها شفافة** وتُركَّب فوق إطار العقد.

### تبديل رسم واحد فقط

من شاشة الإعدادات ← صور الرأس: ارفع البديل وسيعلو على المضمّن. أو ضع الملف
بنفس الاسم في `www/assets/art/` وأعد تشغيل السكربت.

## الطباعة

مستند الطباعة يُبنى كصفحة HTML بمقاس A4 بالضبط، ثم **يُحوَّل إلى PDF** قبل
الإرسال. الـ PDF يثبّت الشكل: الخط العربي ومكان كل حقل والهوامش ومقاس الورقة،
فيخرج العقد بنفس الشكل كل مرة وعلى أي طابعة.

ملفات الخطوط تُضمَّن داخل المستند بصيغة base64، لأن صفحة الطباعة تُحمَّل
منفصلة عن التطبيق — ولولا التضمين لخرج العقد بخط بديل.

**الطريقة الأولى (الافتراضية والمضمونة):** نظام الطباعة المدمج في أندرويد.
تظهر نافذة أندرويد الصغيرة فوق التطبيق والطابعة مختارة مسبقاً، فتكفي ضغطة
ثانية. تتطلب **Epson Print Enabler** أو **Mopria Print Service** على الهاتف.

**الطريقة الثانية (تُجرَّب على الطابعة الفعلية):** طباعة مباشرة عبر **IPP**
بلا أي نافذة. يُحفظ عنوان الطابعة مرة واحدة في الإعدادات، ثم تُختار «طباعة
مباشرة» من شاشة الإعدادات. إن فشلت يرجع التطبيق تلقائياً إلى الطريقة الأولى.

**النسخ:** تُختار بالكبسولات (البائع / المشتري / المعرض) لا برقم. الافتراضي
ثلاث نسخ للعقد ونسختان للوصل، وكل نسخة يُطبع فوقها اسم صاحبها، وتخرج كلها
بضغطة واحدة.

**المشاركة:** زر «مشاركة PDF» يخرّج المستند ملفاً ويفتح قائمة المشاركة
(واتساب وغيره).

## الضبط النهائي — إلزامي قبل الاعتماد

القالب الحالي مبني على وصف العقد في الخطة، لا على مسح ضوئي للورقة الأصلية.
قبل اعتماده:

1. اطبع نسخة تجريبية على ورقة حقيقية.
2. قارنها بالدفتر الأصلي.
3. عدّل المقاسات من متغيّرات `:root` في أعلى قالب الطباعة
   (`--page-pad`, `--frame-pad`, `--base`, الألوان)، ومواضع الحقول من
   الأقسام التي تليها. القالب في `www/css/print.css`، وفي الملف الواحد
   تحت `***** 3) أنماط الطباعة *****`.
4. كرّر حتى التطابق التام ورضا صاحب المعرض.

## ما يحتاجه التطبيق من صاحب المعرض

هذه أمور لم تكن متوفرة وقت البناء، وكلها تُدخَل من **شاشة الإعدادات** بلا
تعديل كود:

- **آخر رقم مستعمل في الدفتر**: يُكتب الرقم الذي يليه في «رقم العقد القادم».
  القيمة الحالية 959 على افتراض أن آخر رقم 00958.
- **نص الشروط الثلاثة**: النص الموجود الآن **مسوّدة مؤقتة** كُتبت بصياغة
  عامة. انسخ الشروط حرفياً من الدفتر الورقي إلى شاشة الإعدادات، ثم علّم
  «اعتُمد نص الشروط». يبقى تنبيه أحمر في الشاشة الأولى حتى تُعلّمها.
- **موديل طابعة Epson**: لتأكيد دعم IPP قبل تفعيل الطباعة المباشرة.

### القرارات المعلّقة في الخطة — كلها خيارات في الإعدادات

| القرار | أين يُحسم |
|---|---|
| «الآلية» أم «السيارة» في متن العقد | إعدادات ← نصوص العقد ← الكلمة المستعملة |
| رقم المحرك إلزامي أم اختياري | إعدادات ← نصوص العقد ← مربّع الاختيار |
| دعم الطابعة لـ IPP | إعدادات ← الطابعة ← طريقة الإرسال |

## سلوك القوائم

- كل قائمة فيها خيار **«أخرى»** يفتح كتابة حرة. بعد حفظ العقد يسأل التطبيق:
  «تريد إضافته للقائمة؟» — نعم تجعله خياراً ثابتاً، ولا تُبقيه في هذا العقد
  فقط.
- **اقتراح المتشابه**: تكتب «ماسي» فيظهر «ماسي فيركسون» الموجود مسبقاً،
  فتختاره بدل إنشاء صيغة جديدة. هذا يمنع تكرار الاسم بصيغ مختلفة ويُبقي
  التقارير نظيفة.
- الكبسولات تُعرض حتى تسعة خيارات؛ وبعدها تُعرض **الأكثر استعمالاً** وزر
  **«المزيد…»** يفتح قائمة كاملة مع بحث.
- **العجلة الدوارة** للتاريخ والوقت وسنة الموديل، تفتح على القيمة الأكثر
  احتمالاً (اللحظة الحالية / سنة قريبة) وتقبل كتابة الرقم مباشرة.

## التخزين

البيانات تُحفظ على الجهاز نفسه في **IndexedDB**. إن منعه المتصفح (يحدث
أحياناً عند فتح الملف مباشرة من القرص) ينتقل التطبيق تلقائياً إلى تخزين
المتصفح البسيط ويستمر العمل.

## النسخ الاحتياطي

في الإعدادات زرّا **تصدير نسخة** و**استيراد نسخة** (ملف واحد يحوي العقود
والوصولات والزبائن والقوائم والإعدادات).

> الورق في الخزنة يحفظ العقد نفسه فقط — لا يحفظ قائمة الزبائن ولا القوائم
> التي كبرت مع الوقت. لذلك يُنصح بتصدير نسخة بين حين وآخر.

## ما لم يُبنَ بعد

- **الحسابات وجدول الأقساط** وتنبيهات الاستحقاق (مؤجَّلة في الخطة للمرحلة
  القادمة).
- **قالب الوصل الصغير** مبني على وصف الخطة، لأن صورة الوصل الورقي الحالي لم
  تصل بعد؛ يُضبط عند وصولها.
