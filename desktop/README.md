# نسخة سطح المكتب (.exe) لتطبيقَي الفيزياء

يبني هذا المجلد ملف **ويندوز تنفيذياً واحداً** لكل تطبيق:

| الملف | التطبيق |
|---|---|
| `dist/phy-sixth-1-2.exe` | المتسعات + الحث الكهرومغناطيسي |
| `dist/phy-sixth-3-4.exe` | التيار المتناوب + الموجات الكهرومغناطيسية |

الملف **محمول (portable)**: يُنقر عليه مرتين فيفتح مباشرة، بلا تثبيت وبلا
إنترنت وبلا أي ملف بجانبه.

## البناء

```bash
cd desktop
npm install                      # مرة واحدة
python3 build-exe.py             # التطبيقان
python3 build-exe.py phy-sixth-1-2   # واحد فقط
```

الشرط الوحيد أن تكون نسخة كل تطبيق أحادية الملف مبنيّة أصلاً
(`python3 phy-sixth-1-2/build-standalone.py`)، لأن `build-exe.py` يأخذها
كما هي.

## كيف يعمل

`main.js` نافذة Electron لا تكرّر منطق التطبيق: تحمّل نفس ملف
`phy-sixth-1-2.html` الذي يعمل في المتصفح. فمصدر الحقيقة واحد — أي تعديل
على التطبيق يصل إلى نسخة الـ exe بمجرد إعادة البناء، ولا يوجد نسختان من
الشيفرة يمكن أن تفترقا.

النافذة بلا شريط قوائم، وخلفيتها بلون التطبيق فلا يظهر وميض أبيض عند
الفتح، وأي رابط خارجي يُفتح بمتصفح النظام بدل أن يبتلع نافذة التطبيق.

## بناء ويندوز من لينكس

- `electron-builder` يحتاج **wine** ليختم أيقونة الملف التنفيذي وبياناته.
  في بيئة بلا `wine32` يفشل لأنه يستدعي `rcedit-ia32.exe`؛ الحل نسخ
  `rcedit-x64.exe` مكانه في ذاكرة `~/.cache/electron-builder/winCodeSign/`.
- حزمة `wine64` في أوبنتو تضع الملف في `/usr/lib/wine/wine64` دون أن
  تضيفه إلى `PATH`، ووصلة رمزية إليه لا تكفي (`could not exec the wine
  loader`) — يلزم سكربت صغير في `/usr/local/bin/wine` يستدعيه بمساره.
- الملف التنفيذي **غير موقّع رقمياً** (لا شهادة توقيع)، فقد يعرض ويندوز
  تحذير SmartScreen أول مرة: «مزيد من المعلومات» ثم «تشغيل على أي حال».

## البنية

```
desktop/
├── main.js           # نافذة Electron
├── build-exe.py      # يبني exe لكل تطبيق
├── package.json      # electron + electron-builder
├── icon.ico          # أيقونة ويندوز (٢٥٦ بكسل فما دون)
└── icon.png          # الأيقونة للأنظمة الأخرى
```

`node_modules/` و `dist/` و `app.html` مستثناة من المستودع: ضخمة ويعاد
توليدها بالأمر أعلاه.
